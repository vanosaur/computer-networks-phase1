# Phase 1 Evidence

This folder contains the evidence collected during the implementation and testing of the Computer Networks Phase 1 project.

The evidence demonstrates the working behavior of the private LAN, DNS, backend services, Nginx reverse proxy, HTTPS/TLS, load balancing, caching, packet analysis, and backend failure handling.

---

## 1. LAN Connectivity

The three macOS machines were connected to the same private LAN.

### Network

```text
Network: 10.7.0.0/19
Subnet Mask: 255.255.224.0
Default Gateway: 10.7.0.1
```

### Machines

```text
Mac 1 — Vani
IP: 10.7.6.20

Mac 2 — Apoorva

```


## 2. Private DNS Evidence

Mac 1 acts as the private DNS server using `dnsmasq`.

The configured DNS mappings are:

```text
app.teambyte.test → 10.7.3.37
api.teambyte.test → 10.7.3.37
```

Mac 2 and Mac 3 use:

```text
10.7.6.20
```

as their DNS server.

### DNS Test

```bash
dig app.teambyte.test
```

Expected result:

```text
status: NOERROR

ANSWER SECTION:
app.teambyte.test.    0    IN    A    10.7.3.37

SERVER: 10.7.6.20#53
```

This verifies that the private DNS server resolves the application domain to the Nginx machine.

## 7. Load Balancing Evidence

Nginx distributes requests between Backend A and Backend B.

The backend is identified using:

```text
X-Backend
```

### Multiple Request Test

```bash
for i in {1..10}; do
  curl -s -D - https://app.teambyte.test:8443/api/status \
  -o /dev/null | grep X-Backend
done
```

Observed distribution:

```text
Request 1  → X-Backend: A
Request 2  → X-Backend: B
Request 3  → X-Backend: A
Request 4  → X-Backend: B
Request 5  → X-Backend: A
Request 6  → X-Backend: B
Request 7  → X-Backend: A
Request 8  → X-Backend: B
Request 9  → X-Backend: A
Request 10 → X-Backend: B
```

This demonstrates round-robin request distribution.

## 8. HTTP Caching Evidence

The `/api/status` endpoint returns:

```text
Cache-Control: max-age=60
```

Express also generates an ETag.

Example:

```text
ETag: W/"1d-/mMMZex8nvIDi44lSUobi0vFg/M"
```

A conditional request using the matching ETag can return:

```text
HTTP/1.1 304 Not Modified
```

This demonstrates HTTP conditional caching.

## 10. Backend Failure Evidence

Backend B was deliberately stopped during the failure demonstration.

### Direct Backend B

When Backend B is stopped, a direct request to:

```text
10.7.3.188:3002
```

fails because the service is no longer running.

### Request Through Nginx

The application can still be accessed through the Nginx edge when the request is handled by the available Backend A.

```text
Client
   |
   v
Nginx :8443
   |
   +------ Backend A → Available
   |
   +------ Backend B → Down
```

This demonstrates service continuity through the available backend.

## 11. Complete End-to-End Verification

The complete application flow is:

```text
Client
   |
   | DNS Query
   v
Mac 1 — dnsmasq
10.7.6.20
   |
   | app.teambyte.test
   | ↓
   | 10.7.3.37
   v
Mac 2 — Nginx
10.7.3.37:8443
   |
   | TLS 1.3
   v
Load Balancer
   |
   +------------------+
   |                  |
   v                  v
Backend A          Backend B
:3001              :3002
```

The final test is:

```bash
curl -i https://app.teambyte.test:8443/api/status
```

A successful response confirms that the complete request path is functioning.
